# FACT-REGISTRY-CONFIG — что система умеет вынимать из сообщения

Держит `fact-registry-config.json` — **определения признаков**. Признак это не ярлык, а
инструкция декомпозиции; определение владельца, через отрицание — так точнее: «нет признака в
реестре — нет инструкции, как это декомпозировать, значит факт не попадёт ни в одну таблицу и
останется просто текстом».

## Кто сюда пишет

🔒 **ТОЛЬКО АГЕНТ РАЗРАБОТКИ, ПРАВЯ ЭТОТ ФАЙЛ И КЛАДЯ КОММИТ.** Этим папка отличается от соседних
конфигов проекта, и отличие не случайное: `APP-CONFIG` и остальные пишет работающая система —
панель или экран настроек, — а реестр правится только через разработку.

Решение владельца 2026-09-06 (подшаг 137-13): формы правки убраны с экрана, вместо них кнопка
отдаёт готовый текст задания, который человек посылает своему Telegram-боту. Оттуда его берёт
агент. **Дверей записи не существует** — у `api/architect/facts` остался только `GET`.

Отсюда и место хранения: пока правка шла формой, хранилищем обязана была быть база — форма пишет
в работающей системе и файла репозитория не видит. Как только писателем стал агент, хранилищем
обязан был стать файл. Иначе у определений два хозяина, и они разойдутся молча.

## Что здесь НЕ лежит

**Значения фактов.** Они в базе: их порождают сообщения, их много и они растут. Здесь только
определения — часть кода, а не пользовательские данные. Таблицы под значения создаёт
`lib/facts/ensure.ts` в рантайме, по одной на признак.

**Встроенные признаки.** Их 36, и они порождаются из кода (`lib/facts/builtin.ts`), потому что
описывают то, что система делает по устройству. Записать их сюда значило бы завести вторую правду,
которая разойдётся с поведением на первом же изменении кода.

## Форма записи

🔒 **ЕДИНСТВЕННЫЙ ИСТОЧНИК ФОРМЫ — `lib/facts/types.ts`, тип `Fact`.** Файла `schema.json` здесь
нет намеренно, в отличие от соседних конфигов: у них схема кормит форму на экране, а здесь формы
нет, и вторая копия описания полей разошлась бы с типом молча.

Обязательное поле ровно одно — `key`. Запись без него отбрасывается целиком.
Всё остальное необязательно и имеет умолчание: `level` → `field`, `valueType` → `text`,
`onMissing` → `silent`, `enabled` → включён.

```json
{
  "facts": [
    {
      "key": "field.amount",
      "level": "field",
      "title": "Сумма",
      "description": "Сколько денег названо в сообщении",
      "valueType": "money",
      "howToFind": "число рядом с валютой или словами «заплатил», «стоит», «за»",
      "onMissing": "silent"
    }
  ]
}
```

🔒 **ЗАКРЫТЫЕ СПИСКИ СВЕРЯЕТ `lib/facts/store.ts` ПРИ ЧТЕНИИ, А НЕ ОБЕЩАЕТ АВТОР ФАЙЛА.** Файл
пишется руками, значит в нём бывают опечатки: чужое значение `level` или `valueType` становится
умолчанием, а не ложится в реестр правдоподобной ложью.

🛑 **КЛЮЧ ПРОВЕРЯЕТСЯ ОТДЕЛЬНО, ПОТОМУ ЧТО ИЗ НЕГО РОЖДАЕТСЯ ИМЯ ТАБЛИЦЫ.** Пропущенный без
проверки, он перестал бы быть именем и стал бы SQL. Ключ, из которого имя не собирается, признак не
скрывает: строка «где живёт» говорит «имя недопустимо: таблицы нет» — молчание тут читалось бы как
«работает». Измерено: `field.money; DROP TABLE tgdesk_messages` таблицы не получает.

## Как читается

Статическим импортом в `lib/facts/store.ts`, то есть **файл входит в сборку**. Правка определений
приезжает коммитом и пересборкой — другого пути к ней нет, — поэтому перечитывать файл на каждом
запросе незачем. Этим папка снова отличается от `APP-CONFIG`, который читается на каждом запросе:
там правка приходит из работающей панели и обязана быть видна без пересборки.
