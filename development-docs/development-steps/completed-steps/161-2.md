# 161-2 — утверждение и предположение стали сущностями, а не дисциплиной модели

**Репозиторий:** `fractera-telegrambot-starter`, `main`. **Коммит:** `a520ab3`. **Дата:** 2026-09-08.
**Сервер:** `pnpm build` = 0, прибор `claim-basis-161-2` — **10/10**.

## Что делали и как

Первый из двух долгов §8.2 стандарта памяти закрыт **конструкцией**: у значения признака появились
две колонки — `claim` (`fact` — человек сказал прямо; `guess` — система вывела) и `basis` (на чём
стоит вывод). Правка тронула четыре места **одной операцией**, как велит закон «колонка — не
таблица»: образец формы · лестница `FACT_TABLE_LATE_COLUMNS` · список сверки `FACT_TABLE_COLUMNS` ·
чтение в `recall`.

Сторож стоит в **единственном писателе** `writeFact`, рядом со сторожем глубины и по той же причине:
это единственное место, где значение ложится в таблицу. Три отказа, и каждый называет причину
словами: предположение без основания · основание без предположения · род вне закрытого списка.

🔒 **ВТОРОЙ ОТКАЗ — НЕ СИММЕТРИЯ РАДИ КРАСОТЫ.** Присланное поле, которое молча ничего не значит,
есть отдельный класс дефекта (закон 143): вызывающий уверен, что объяснил происхождение, а в таблице
лежит уверенное утверждение без пометки.

## Доказательства — две плоскости, названные в ТЗ заранее

### 1. Схема живой базы: колонок «до» нет, «после» есть

```
✓ «до»: колонок рода записи нет — 12 колонок
✓ запись прошла: personal
✓ «после»: лестница дописала claim, basis
```

**Что запущено:** `node scripts/probe/claim-basis-161-2.mjs` на сервере. Прибор готовит таблицу
`fact_person_language` **в старой форме** — такой, какая на живой машине у всех девяти существующих
таблиц, — и снимает список колонок до записи.
**Что доказывает:** лестница `ALTER` исполняется на уже созданной таблице, а не только на чистой.
**Негативный контроль встроен в замер:** совпадение списков «до» и «после» означало бы, что лестница
не отработала; «до» снимается **до** работы, вспомнить о нём в конце нельзя.
**Как выглядело бы без правки:** колонки объявлены в форме, на живых таблицах их нет, `INSERT`
поимённо падает целиком — и снаружи это выглядит как «памяти не существует» (ровно так этот класс
проявился позавчера в 143).

### 2. Поведение двери и чтение обратно

```
✓ предположение без основания отвергнуто: guess-without-basis
✓ предположение С основанием записано: personal
✓ основание без предположения: basis-without-guess
✓ выдуманный род записи: bad-claim
✓ предположение читается помеченным: claim=guess, основание «человек писал ответы по-английски…»
✓ сказанное человеком осталось без пометки: value=русский, claim=null
✓ после уборки таблицы прибора не осталось
```

**Что доказывает:** разница между сказанным и выведенным существует в данных и доезжает до того, кто
спрашивает.
**Негативный контроль:** обычная запись **не становится** предположением — `claim=null`. Без этой
строки первый замер доказывал бы только, что поле возвращается.
**Как выглядело бы без правки:** обе записи неотличимы, и через неделю догадка читается как
свидетельство человека.

## Ошибки

1. 🛑 **ОБРАТНЫЕ КАВЫЧКИ ВНУТРИ ШАБЛОННОЙ СТРОКИ ЗАКРЫЛИ ЕЁ.** Я написал в SQL-комментарии формы
   таблицы `` `fact` `` и `` `guess` `` — по привычке оформления. Форма разорвалась на середине, а
   компилятор сообщил про «Module declaration names may only use quoted strings», то есть увёл от
   причины. Поймано `tsc --noEmit` до отправки.
   🔒 **Это третий за два дня случай одного класса** — обратная кавычка и обратный слэш ломают текст
   молча и не там, где написаны. Правило проекта уже есть; сюда добавлено предупреждение **внутри
   самого комментария**, рядом с местом, где ошибиться легче всего.
2. **Прибор обогнал старт службы.** После `pm2 reload` я ждал фиксированные 6 секунд — и получил
   `ECONNREFUSED` при исправной службе, поднявшейся секундой позже.
   🔒 **Лечение — ждать порт по факту, а не по таймеру:** цикл `curl` до `200`. Фиксированная пауза
   — это гонка, у которой сегодня выигрываешь, а завтра нет; и проигрыш выглядит как отказ двери.

## Эволюция навыков

- **`use-testing`** — правило «названный заранее контроль» сработало буквально: снимок «до» имеет
  смысл только снятым до работы, и в ТЗ он был назван заранее.
- **Предложение:** в навык `use-testing` добавить строку о **готовности среды**: замер после
  перезапуска службы начинается с ожидания порта по факту. Сегодня это знание живёт в приборах,
  которые его уже пережили, — то есть у каждого своё.
