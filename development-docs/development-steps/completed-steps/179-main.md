## Доказательства (обе службы, один прибор)

**Плоскость A — маршрут выхода.** До: `redirectUrl=…%2Fru`. После:
`redirectUrl=https%3A%2F%2Fmemory.aifa.dev%2Fru%2Fwelcome` и то же для `chat.aifa.dev`.

**Плоскость B — HTML страницы без входа.** `/ru/welcome` → `200` у обеих; ссылка
`login?callbackUrl=https%3A%2F%2F<служба>.aifa.dev%2Fru` есть; обе подписи есть; `href="/ru"` есть.
**Негативные контроли:** `login?redirectUrl=` — 0 · «Адрес службы входа пока не настроен» — 0 ·
русского на `/en` — 0 · лид памяти в чате — 0, лид чата в памяти — 0.

🛑 **НЕДОСТИЖИМОЕ ДЛЯ АГЕНТА:** сам выход с живой сессией и возврат после входа проверяются куками
владельца.

## Ошибки и находки

🛑 **ДОСЛОВНАЯ КОПИЯ СЛОМАЛА БЫ ПАМЯТЬ.** `publicAuthUrl()` чата выводил адрес входа только для хоста
`chat.` — у памяти он вернул бы пустую строку. Правка копии объявлена в плане до кода и сделана:
приставка заменяется у любого поддомена.

🛑 **ПОПУТНЫЙ ДЕФЕКТ ЧАТА, НАЙДЕННЫЙ РАЗВЕДКОЙ:** кнопка входа слала `redirectUrl`, а экран входа
читает только `callbackUrl` (`services/auth/.../login-placeholder.client.tsx:33`). Возврат терялся
молча: после входа человек оставался на экране службы входа. Исправлено в обеих службах.
