# 160-4 — сторож глубины: в личную таблицу не проходит второй порядок

**Коммиты:** `283216f` (сторож и вход), `1e4d1a4`-серия правок по прибору.
**Дата:** 2026-09-08. Стандарт — `development-docs/MEMORY-STANDARD.md` §2.3.

## Что делали и как

`lib/facts/depth-guard.ts` — три проверки: порядок субъекта · один уровень вложенности · потолок
полей. Встроен в `writeFact` — **единственное место, где значение ложится в таблицу**. Сторож у
двери пропустил бы запись из соседнего кода, а запрет, который можно обойти, — не запрет.

**Добавлен вид значения `object`:** глубина 1 хранится объектом, а не прозой. `{name, role,
birthYear}` даёт и отбор по роли, и вычисление возраста; `"Рада — дочь, 16 лет"` не даёт ничего и
устаревает молча.

## Доказательства

**Прибор на живой двери** (`scripts/probe/depth-and-many-160.mjs`, сервер), 8 из 8:

```
✓ простая строка записана: fact_person_name
✓ вложенный объект отвергнут: nested-object — «поле «car» содержит вложенный объект — это глубина 2»
✓ плоский объект ПРОШЁЛ: fact_person_important_people — сторож отвергает глубину, а не объекты
✓ массив отвергнут: not-an-object
PROBE_RC=0
```

*Негативный контроль назван заранее и стоит рядом:* плоский объект обязан **пройти**. Без него
первый замер доказывал бы лишь, что объекты не принимаются вовсе.

## Ошибки — три, и все нашёл прибор

- ✗ **Дверь приводила значение к строке ДО сторожа** (`String(args.value ?? "")`). Объект становился
  `[object Object]`, сторож видел строку и пропускал: **запрет существовал, а данные второго порядка
  всё равно проходили**. 🔒 Класс шире случая: **приведение типа перед проверкой обезоруживает
  проверку**.
- ✗ **Проверка аргументов отвергала объект раньше сторожа** — `bad-args` вместо разбора. Правило:
  проверка формы не перехватывает то, для чего есть проверка смысла.
- ✗ **Массив давал «должен быть value, а пришло object»** — сообщение, из которого человеку нечего
  понять. Пропущен к сторожу, тот отвечает по делу.

## Эволюция навыков

🔒 **В `use-testing` просится приём: проверять запрет ЧЕРЕЗ ТУ ЖЕ ДВЕРЬ, ЧТО И ЖИЗНЬ.** Сторож,
проверенный вызовом функции напрямую, был бы зелёным — и всё равно не работал бы, потому что дверь
портила значение по дороге. Три из трёх дефектов жили **между** проверкой и правилом.
