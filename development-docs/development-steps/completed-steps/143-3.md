# 143-3 — лента прогона: строки разбора получают адрес и переживают разговор

**Коммиты:** `70e4a5c` (код), `a216a88` (указатель) в `fractera-telegrambot-starter`, ветка `main`.
**Дата:** 2026-09-08. Замысел — `PASSPORT.md` §3е.

## Что делали и как

Завели таблицу `automation_rows` и её единственного писателя. Первая строка (`intake`) пишется
дверью сепарации — единственной точкой, через которую сообщение попадает в систему.

**Решение, принятое по ходу:** 🔒 **стол разбора и лента прогона — разные вещи, но форма строки
одна.** `task_current` отвечает на «что происходит сейчас» (одна строка, живёт 30 минут,
**заменяется следующим сообщением**); лента — на «что случилось за прогон номера N» и обязана
пережить разговор, потому что по ней считаются условия закрытия. Обе пишутся типом `TaskRow`:
вторая форма разошлась бы с первой, и экран показывал бы не то, по чему принимаются решения.

## Доказательства

**1. База — прибор на живом слое данных** (`scripts/probe/automation-rows-143-3.mjs`, сервер):

```
===PROBE_143_3===
✓ первая строка легла: 1
✓ после второй записи строк: 2 (ждём 2)
✓ первая строка не переписана: «первое сообщение»
✓ чужой номер видит строк: 0 (ждём 0)
✓ закрытый список видов работает: intake да, вымышленный нет
✓ строк без признака у B: 1 (ждём 1) — материал для 143-7
✓ после уборки строк осталось: 0
PROBE_RC=0
```

*Что доказывает:* строки копятся по номеру и не стирают друг друга — то, чего стол разбора не умеет
по устройству. *Негативный контроль:* чужой номер видит ноль строк; будь запрос без `WHERE`, он
показал бы чужое. *Как выглядело бы без правки:* писателя не было вовсе — ноль строк у любого номера.

**2. Код — измерение, с которого начался подшаг:**

```
кто зовёт appendRows во всём дереве .......... 0
```

*Что доказывает:* лента строк была построена целиком (`TaskRow` с `payload`, `next`, `rejected`,
`confidence`) и **не имела ни одного писателя**. Способность, написанная и не подключённая, снаружи
неотличима от отсутствующей.

## Ошибки

- ✗ **Правка по многострочному образцу молча не сработала**, и `node` при этом отрапортовал успех:
  `String.replace` без совпадения возвращает исходный текст. Причина — смешанные CRLF и LF в дереве.
  🔒 **Лечение принято как правило: правки построчно**, а не по многострочному образцу. Проверка —
  `grep -c` после правки, а не доверие к тому, что скрипт «прошёл».

## Эволюция навыков

🔒 **В `use-testing` просится приём: у правки файла тоже есть негативный контроль** — `grep` на
изменённое ПОСЛЕ записи. Скрипт, сообщивший «готово», доказывает, что скрипт дошёл до конца, а не
что файл изменился. Ровно тот же класс, что «сборка не бывает доказательством».
