# 141-3 — охват считается ОДИН раз на сообщение и наследуется его фактами

**Коммит:** `134c734` в `fractera-telegrambot-starter`, ветка `new-step-A`. **Дата:** 2026-09-07.
**Пятый подшаг серии A.** Замысел — `PASSPORT.md` §3г.

## Что делали и как

`lib/facts/scope-resolve.ts`: `neededDimensions()` собирает **объединение** измерений по сработавшим
признакам · `resolveScope()` спрашивает источники по порядку доверия · `applyScope()` раздаёт один
ключ всем фактам сообщения.

**Четыре решения по ходу:**

1. **Спрашивается измерение, а не признак.** Два признака, зависящие от города, дают одно
   измерение — спрашивать дважды нечего. Именно это и есть предмет подшага.
2. **Порядок источников — порядок доверия:** сказанное сейчас сильнее сказанного вчера, вчерашнее
   сильнее, чем ничего. Первый ответивший закрывает вопрос, остальных не спрашивают.
3. **Половина охвата — не охват.** Ключ строится, только если известны все объявленные измерения;
   иначе вышел бы охват **шире объявленного**, то есть лживый. Недостающее уходит в `missing` — это
   вход для вопроса человеку (141-7).
4. **Наследуют все факты сообщения, включая не объявившие зависимости.** Факт всё равно случился
   где-то; знание дешёвое и понадобится, как только человек объявит зависимость задним числом.
   Обратное потребовало бы разобрать прошлое заново, а разобрать его нечем.

🛑 **Живого разбора сообщения в службе нет** (§1 паспорта — сепарация не построена). Здесь узел,
который разбор позовёт; источники приходят параметром. Сказано в самом модуле, чтобы «готово» не
читалось как «работает в проде».

## Доказательства

**1. Прибор на функции** (`npx tsx scripts/probe/scope-resolve-141-3.mjs`, `PROBE_RC=0`):

```
✓ нужных измерений на три признака: ["field.geo"]
ключ: «field-geo=madrid», ответил: сказано сейчас
✓ обращений к источникам на ДВА зависимых признака: 1
✓ обращений, когда зависимых признаков нет: 0
✓ ключ пуст, когда охват не объявлен: ""
порядок доверия: ответил «сказано сейчас», обращений 2
✓ молчащий источник не мешает следующему: "field-geo=madrid"
✓ ключ пуст, если известна половина: ""
✓ недостающее названо поимённо: ["lang"]
✓ охват унаследован всеми строками: ["field-geo=madrid","field-geo=madrid"]
```

*Что доказывает:* счётчик обращений — это и есть предмет подшага, и он равен единице на два
зависимых признака.
*Негативных контролей три:* «зависимых нет → 0 обращений» (иначе счётчик мерил бы что угодно) ·
«молчащий источник» (иначе порядок доверия не проверен) · «известна половина» (иначе неполный охват
молча стал бы полным).

**2. База — наследование через РАЗНЫЕ таблицы** (живой слой данных, `INHERIT_RC=0`):

```
охватов у фактов одного сообщения: 2 → ["field-geo=madrid","field-geo=madrid"]
все одинаковы: верно
чужой охват нашёл: 0 — обязан быть 0
свой охват нашёл:  1 — обязан быть 1
```

*Что доказывает:* два факта одного сообщения, лежащие в **разных** таблицах, несут один ключ — то
есть охват действительно принадлежит сообщению, а не признаку.
*Как выглядело бы без правки:* каждый признак получил бы свой ответ, и «Мадрид» одного факта не
совпал бы с «Мадридом» другого при малейшем расхождении источников.

**3. Типы:** `TSC_RC=0`.

## Ошибки

Ошибок в этом подшаге не было — впервые за серию. Приёмы, оплаченные раньше, сработали заранее:
образец правки безразличен к переводу строки, прибор без типов в `.mjs`, вывод в файл и код возврата
сразу после команды.

## Эволюция навыков

**Наблюдение, которое стоит записать:** три подшага подряд доказывались **счётчиком**, а не
содержимым — сколько раз позвали, сколько строк записали, сколько нашли. Это дешёвый и сильный род
доказательства для узлов без экрана, и он заслуживает строки в `use-testing` рядом с негативным
контролем: **измеряй не только «что получилось», но и «сколько это стоило вызовов»**.
