## Доказательства

**Первое — сквозной путь, которого не было.** Дверь сепарации приняла срок с зоной и вернула
`timezoneRemembered: true`; `recall` отдал факт из **первой порождённой таблицы признака в проекте**:

```
{"found":true,"key":"person.timezone","table":"fact_person_timezone","total":1,
 "items":[{"id":1,"value":"Atlantic/Canary","subject":"self","status":"current",
           "at":"2026-09-07T22:22:32Z"}]}
```

**Второе — самопроверка навыка (§6), восемь фраз словами человека:**

```
меня зовут Рома        → person.name[field]
давай на ты            → person.address-form[field]
не надо длинных        → person.tone[field]
никогда мне не звони   → person.avoid[field]
Миша мой коллега       → person.important-people[field]
я живу на канарах      → intent.where[intent] person.city[field]
считай в евро          → person.currency[field]
не пиши после десяти   → person.active-hours[field]
```

Восемь из восьми находят нужный признак первым. **Негативный контроль встроен:** «я живу на канарах»
даёт ДВА попадания разных уровней — это верно, и `level` их различает.

**Третье — прибор:** `✓ случаев 19, провалено 0`, включая новый случай про незаполненный признак.

## Ошибки — четыре, и все свои

✗ **`onMissing: "note"` у первого же признака** — такого значения нет, список закрыт
(`silent | ask | join`), разбор **молча падал на `silent`**. То есть признак не спрашивал бы
недостающее. Найдено чтением типов при заведении остальных двенадцати. Мой собственный класс 7 —
«успех по умолчанию».

✗ **`recall` по незаполненному признаку отвечал «слой данных не ответил»** вместо «значений ещё не
было». Для тринадцати пустых ячеек это был бы ЕДИНСТВЕННЫЙ ответ — человек видел бы поломку там, где
просто ещё ничего не сказал. Класс 6, найден живым прогоном.

✗ **Самопроверка навыка сначала показала провал**, которого не было: мой тест брал только лучшее
совпадение, а `find` возвращает список. `intent.where` и `person.timezone` находятся с **равным**
счётом — оба верны. Из этого выросло полезное: `level` в указателе.

✗ **Случай прибора вставился ВНУТРЬ соседнего случая** — скрипт нашёл первую `];` в файле, а не конец
массива. `node --check` прошёл (синтаксис остался валидным), прибор напечатал 18 вместо 19, и случай
не исполнялся. **Позиция вместо значения — тот же класс, что уже ловил меня в 157-5.**

## Эволюция навыков

✅ **`create-registry-entry` прогнан впервые** и прошёл: порядок «сначала triggers и answers» дал
восемь попаданий из восьми. Самопроверка §6 оказалась самой ценной частью — она нашла и ложный
провал, и настоящее улучшение.

**Заведён `first-acquaintance`** — ⬜ до первого живого разговора. Его правило, ради которого он и

по одному вопросу, и только когда ответ нужен сейчас.
