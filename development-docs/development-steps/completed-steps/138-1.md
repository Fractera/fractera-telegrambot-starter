# 138-1 — таблица автоматизаций и счётчик номеров

**Коммит:** `08a598c` в `fractera-telegrambot-starter`, ветка `new-step-A`. **Дата:** 2026-09-07.
**Первый подшаг серии A.**

## Что делали и как

Завели таблицу `automations` и номер, который человек произносит вслух. Форма и её починка лежат в
одном файле (`lib/automations/table.ts`) — тот же закон, что у таблиц признаков: правящий образец
обязан видеть лестницу `ALTER`. Чтение и запись (`store.ts`) идут через единственную дверь
`dataFetch`; колонки называются поимённо.

**Три решения, принятые по ходу и названные вслух:**

1. **`AUTOINCREMENT` обязателен.** Без него SQLite выдаёт `max(id) + 1` и после удаления последней
   строки **переиспользует её номер**. Номер уже произнесён человеком, и второй жизни у него быть
   не может: ссылка молча начнёт указывать на чужую работу.
2. **Колонка названа `confirm_state`, а не `state`.** У автоматизации две независимые оси состояния:
   подтверждён ли НОМЕР (§3а) и где она в РАБОЧЕМ ПОТОКЕ (§3е). Оба зовутся «состоянием»; в одной
   колонке «подтверждено» перестало бы отличаться от «закрыто». Разведено до столкновения.
3. **Лестница поздних колонок заведена пустой** — чтобы шаг 144 не изобрёл второй механизм:
   `CREATE TABLE IF NOT EXISTS` на работающем сервере не делает ничего.

## Доказательства

**1. База — прогон прибора на живом слое данных `:3300`** (`scripts/probe/automations-138-1.mjs`):

```
===PROBE_138_1===
таблица ДО прогона: нет
таблица ПОСЛЕ создания: есть
три вставки подряд: 1, 2, 3
удалена ПОСЛЕДНЯЯ (3), следующая вставка: 4
НОМЕР НЕ ПЕРЕИСПОЛЬЗОВАН — верно
AUTOINCREMENT в определении: есть
после уборки: строк 0, счётчик сброшен
===PROBE_138_1===DONE
PROBE_RC=0
```

*Что доказывает:* номер выдаёт база, растёт от единицы и не идёт назад.
*Как выглядело бы без правки:* без `AUTOINCREMENT` четвёртая вставка вернула бы `3` — номер
удалённой. **Негативный контроль встроен: удаляется ПОСЛЕДНЯЯ строка** — единственный случай,
который различает две реализации.
*Уборка:* прибор отказывается работать, если в таблице есть чужие строки, и после себя возвращает
ноль строк и сброшенный счётчик — первая настоящая автоматизация получит номер 1.

**2. Код — единственная дверь:**

```
обход двери внутри lib/automations ........... 0
негативный контроль (тот же образец
   находит саму дверь в data-service.ts) ..... 1
SELECT * в lib/automations ................... 0
обращений через dataFetch .................... 3
```

*Что доказывает:* второй двери к данным не заведено. *Негативный контроль:* образец не «слепой» —
он находит единственное законное место.

**3. Типы:** `npx tsc --noEmit` → `TSC_RC=0`.

## Ошибки

- ✗ **Ошибка в моём же ТЗ, найденная прибором.** ТЗ 138-1 предлагало «удалить ВТОРУЮ из трёх, затем
  вставить четвёртую». Этот случай **ничего не различает**: обычный `INTEGER PRIMARY KEY` тоже даёт
  `4`, потому что считает `max(id) + 1`. Различает только удаление **последней** строки. Прибор
  сделан по исправленному случаю; ТЗ подлежит правке при перезакрытии.
- ✗ **Ложный `TSC_RC=0` в первом прогоне.** `npx tsc --noEmit | tail -5` печатает код `tail`. Тот же
  класс, что записан в законах про `npm run build | tail`. Исправлено: код берётся у `tsc`.
  Заодно всплыл мусор: устаревший `.next/types/validator.ts` ссылался на удалённые маршруты;
  снимается `rm -rf .next/types` перед проверкой.
- 🛑 **Попутный долг, найденный измерением и НЕ починенный здесь:** `lib/fractera/media.ts` и
  `app/api/fractera/openai-key/route.ts` ходят к слою данных **своим** `fetch` мимо `dataFetch` —
  две копии адреса и секрета. Разойдутся в день, когда владелец поменяет ключ в одном месте из двух.
  Починка — отдельная работа, здесь она была бы чужой правкой внутри подшага.

## Эволюция навыков

Читались: `use-development-steps` (закрытие подшага), `use-testing` (негативный контроль).
**Что стоит добавить в `use-testing`:** правило «названный заранее негативный контроль проверяется на
различимость» — контроль, который дал бы тот же результат и без правки, есть украшение, а не
доказательство. Здесь это поймано случайно, при написании прибора, а должно ловиться правилом.
