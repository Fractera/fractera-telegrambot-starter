# 161-3 — чтение: лестница уехала внутрь ящика, бюджет стал параметром

**Репозиторий:** `fractera-telegrambot-starter`, `main`. **Коммиты:** `3101906` · `7f4573f`.
**Дата:** 2026-09-08. **Прибор `read-ladder-161-3` — 12/12**, сборка `BUILD_RC=0`.

## Что делали и как

Второй долг §8.2 закрыт: **бюджет углубления стал параметром**, а лестница источников переехала
внутрь `read()`. Снаружи это один вопрос; внутри — ступени: значения признаков о человеке ·
механический поиск по его словам, когда ключ неизвестен · знание об окружении, и **только при
`budget: "deep"`**.

Ответ несёт две вещи, которых у прежнего чтения не было: **пометку рода** у каждого значения
(161-2) и блок `deeper` — стоит ли идти глубже, во что обойдётся и что это добавит. Цена названа в
секундах, потому что человеку нечего делать с миллисекундами, а агенту — с абстрактным «дорого».

🔒 **ЦЕНА ИЗМЕРЕНА ДО ТОГО, КАК ПОПАЛА В КОД:** личная таблица — **30 мс**, вопрос к знанию об
окружении — **885 · 4777 · 5016 мс** на трёх вопросах подряд (сервер, 2026-09-08). В коде стоит
пять секунд — **худшее измеренное**, а не среднее: обещание должно выполняться в плохом случае.

## Доказательства — две плоскости, названные в ТЗ заранее

### 1. Время и число обращений

```
✓ по ключу ответ за 26 мс — из записанного, без обращения к связям
✓ «что ты знаешь обо мне» ОДНИМ вызовом: 2 значений за 221 мс
✓ fast на незнакомый вопрос: не нашёл в записанном за 30 мс и в связи НЕ ходил
✓ ответ сам предлагает глубину и называет цену: 5 с
✓ deep нашёл в связях за 339 мс: «О человеке по фамилии Ратмиров известно, что он держал пасеку…»
✓ глубина дороже быстрого пути: 339 мс против 30 мс
```

**Что доказывает:** бюджет не числится в договоре, а управляет поведением — при `fast` обращения к
связям не происходит вовсе, и это видно по времени.
**Негативный контроль:** тот же вопрос с `deep` идёт другой дорогой и стоит на порядок дороже.
🛑 **Честная оговорка о числе 339 мс:** это повторный вопрос, и хранилище отдало его из своего кэша.
Первое измерение того же пути дало 3414 мс. Обещанные пять секунд остаются верхней границей.

### 2. Форма ответа

```
✓ пришедшее из связей помечено предположением: claim=guess
✓ выведенное значение помечено: person.currency claim=guess
✓ сказанное человеком без пометки: person.occupation claim=null
✓ при deep глубже не предлагается: «глубже идти уже некуда»
✓ пустой признак: 200, found=false, «признак есть, значений у него пока нет»
```

**Что доказывает:** ответ честен о происхождении каждого значения; собранное моделью из связей
помечается предположением **по устройству**, а не по доброй воле вызывающего.
**Негативный контроль:** сказанное человеком предположением не становится; при `deep` предложение
углубиться исчезает.

## Ошибки и находки

1. 🛑 **ГЛАВНАЯ НАХОДКА, И ОНА ШИРЕ ЭТОГО ПОДШАГА: ПОИСК ПО СВЯЗЯМ ЧУВСТВИТЕЛЕН К ФОРМЕ ВОПРОСА.**
   Один документ, четыре формы вопроса, замер подряд:

   | Вопрос | Режим | Итог |
   |---|---|---|
   | «Ратмиров» | по связям | нашёл |
   | «Что известно о человеке по фамилии Ратмиров?» | по связям | нашёл |
   | «что известно о человеке по фамилии Ратмиров» | по связям | **не нашёл** |
   | та же строчная фраза | вектором | нашёл |

   🔒 **Объяснение механическое:** поиск по связям вынимает из вопроса ИМЕНА и сверяет их с именами
   сущностей — регистр и лишние слова ему мешают; вектор сравнивает смысл целой фразы.
   🛑 **А человек в Telegram пишет строчными и целыми фразами** — то есть ровно в той форме, на
   которой связи молчат. Отсюда правило внутри ящика: короткий вопрос (до трёх слов, похож на имя)
   идёт по связям, длинный — вектором.
2. ✗ **МОЙ ПРИБОР ОБЪЯВИЛ ЖИВУЮ НАХОДКУ ОТКАЗОМ.** Образец искал русские слова, а хранилище на
   строчный вопрос ответило **по-английски**: «is a person who has been maintaining a beehive».
   🔒 **Негативный контроль сам нуждается в проверке** — закон 143 подтверждён третий раз.
3. 🛑 **ДОЛГ, НАЗВАННЫЙ ЧЕСТНО:** знание об окружении иногда отвечает по-английски на русский
   вопрос. Для владельца, который читает ответы в Telegram, это дефект; чинится не здесь, и потому
   назван, а не спрятан.
