# Шаг 177 — Output каждого слоя: лог как Markdown-документ, один на агента и человека

## 1. Пересказ и решения владельца

**Предмет просьбы.** Агенту закрыт вход в слои — значит у каждого слоя должен быть **Output**, по
которому и агент, и человек понимают, что внутри происходит. Источник ОДИН: Markdown-документ.
Агент читает файл, человек читает страницу, порождённую из того же файла. Кнопка «Очистить историю»
стирает документ — и пустоту видят оба. Начинаем с памяти (`:3700`), потом переносим на агента
Telegram (`:3600`).

## 2. Разведка — что берём готовым

| Что | Где | Почему не строим заново |
|---|---|---|
| конвейер входа | куки → `${AUTH_SERVICE_URL}/api/session` → `{email, roles}` | закон: доказанный конвейер входа не улучшают |
| кука видна поддомену | служба входа ставит её на `COOKIE_DOMAIN=.aifa.dev` | общий секрет между службами не нужен |
| образец nginx-блока | `/etc/nginx/sites-enabled/fractera-custom`, блок `chat.aifa.dev` | там уже решены OCSP, таймауты, размер тела |
| список поддоменов платформы | `bridges/app/lib/server-ip.ts` → `SUBDOMAINS` | оттуда берутся SAN certbot, nginx и проверка DNS |
| договор памяти | `contract.mjs`, три метода | новые методы добавляются туда же, сторож `npm run check` |

## 3. Известные ограничения

| Инвариант | Что случится при нарушении |
|---|---|
| у памяти **ноль зависимостей** | любой пакет ради страницы — ещё один способ не запуститься на чистой машине |
| память слушает **только петлю** | nginx ходит туда же; выставить её наружу значит открыть службу без замка |
| **служба, не названная в `SUBDOMAINS`, по домену недостижима** | оттуда SAN certbot, nginx-блоки и проверка DNS |
| сертификат выпускается **после** DNS | HTTP-01 не пройдёт на несуществующем имени |
| ответ чужой службы читается **целиком** | `:3001` может ответить `200` с телом без `email` |
| лог — рантайм-данные, **не код** | попав в git, он утечёт клиенту и раздует репозиторий |

## 4. Наблюдаемые результаты

1. После вызова памяти в её Markdown-документе появляется запись о том, что произошло внутри.
2. Метод договора отдаёт этот документ целиком; второй метод его очищает, и файл становится пустым.
3. Страница памяти показывает то же самое человеку; без роли `architect` она не отдаётся.
4. Кнопка «Очистить историю» стирает документ, и агент видит пустоту тем же чтением файла.
5. `memory.aifa.dev` отвечает по HTTPS.
6. У агента Telegram появляется свой документ той же формы.

- Логи служб `:3000`, `:3300`, `:3400`, `:3500` — их черёд после того, как форма докажет себя дважды.
