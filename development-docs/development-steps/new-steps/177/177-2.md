# 177-2 — два метода договора: отдать документ и очистить его

## 1. Что строится — файлы и двери поимённо

| Файл | Что с ним |
|---|---|
| `contract.mjs` | два метода: отдать документ и очистить его. Версия поднимается по semver |
| `server.js` | исполнители подключены в `RUN` — по имени из договора, а не списком в маршрутизаторе |
| `lib/journal.mjs` | `readAll()` и `clear()` есть с 177-1, здесь они получают дверь |

🔒 **ИМЕНА МЕТОДОВ ЧЕЛОВЕЧЕСКИЕ, КАК У СОСЕДЕЙ ПО ДОГОВОРУ.** Рядом живут `remember`, `recall`,
`people`; техническое имя выбивалось бы из ряда и выдало бы, что договор писали в два захода.

🔒 **ОЧИСТКА ОТВЕЧАЕТ, СКОЛЬКО СТЁРЛА.** «Готово» и «стёрто 214 записей» — разные ответы; второй
доказывает, что стирали именно то, что было.

🛑 **ОЧИСТКА НЕОБРАТИМА, И ДОГОВОР ГОВОРИТ ЭТО СЛОВАМИ.** Метод, молчащий о необратимости, однажды
позовут «посмотреть, что будет».

## 2. Что считается готовым

Метод чтения возвращает документ целиком; метод очистки делает его пустым и называет число стёртых
записей.

## 3. Чем доказывается — две плоскости, названы заранее

**Плоскость A — поведение двери.** Позвать чтение, увидеть текст; позвать очистку, увидеть число;
позвать чтение снова — документ пуст.
**Негативный контроль:** чтение без секрета машины обязано дать `401`, а не текст.

**Плоскость B — сторож договора.** `npm run check` проходит: версия поднята по semver, у методов
сказано когда звать, что вернут и что при промахе, типы только из JSON Schema.
**Негативный контроль здесь:** сторож обязан ронять проверку, если у нового метода убрать описание —
проверяется временной правкой и возвратом.

## 4. На что опирается
