# 171-3 — `separate` возвращает МАРШРУТ, а не только род

## 1. Что строится

- `lib/task/separation.ts` — карта «род → маршрут»: короткая фраза о том, что делать дальше, рядом
  с уже существующей `categoryLine`. **Один источник**, из которого маршрут и печатается, и
  типизируется; второй список разошёлся бы с первым молча.
- `app/api/agent/separate/route.ts` — поле `route` во **всех** ответах `ok:true`, включая ранний
  возврат на роде `general` (`route.ts:103`).
- `scripts/agent/intake-preloader.js` — маршрут доезжает до агента текстом ответа инструмента, а не
  прячется в поле, которое никто не читает.

**Зачем при живом 171-2.** Инструкция говорит, как поступать вообще; маршрут приходит **в момент
решения** и про **это** сообщение. Тот, кто всё же зашёл в дверь, обязан получить ответ, что делать
дальше, — иначе он изобретёт его сам.

## 2. Что считается готовым

`curl` двери с каждым из четырёх рабочих родов печатает **свой** маршрут; неизвестный род
по-прежнему получает отказ, а не маршрут по умолчанию.

## 3. Чем доказывается — две плоскости, названы заранее

**Плоскость 1 — дверь (сеть).** Пять вызовов `curl`: четыре рода — четыре разных значения `route`.
**Негативный контроль:** пятый вызов с `kind: "чушь"` обязан дать `unknown-kind` и **не** содержать
поля `route`. Маршрут по умолчанию у неизвестного рода — худший исход: он выглядит как знание.
*Как выглядело бы без правки:* поля `route` нет ни в одном ответе.

**Плоскость 2 — хранилище (данные).** Число строк в таблице автоматизаций **до и после** десяти
вызовов с родом `general` **совпадает**.
*Что доказывает:* добавление маршрута не превратило общий разговор в записываемую работу — то есть
дорога осталась бесплатной по данным. Совпадение чисел и есть доказательство неизменности.

## 4. На что опирается

Ни на что. Может идти параллельно 171-2, доставляется после него.

## 5. Чего в подшаг не входит

Изменение набора родов, логики `continues`, нумерации работ. Дверь **типизирует** решение агента и
не начинает разбирать сообщение сама — второй разбор стоил бы второго вызова модели.
