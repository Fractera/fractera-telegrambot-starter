# Шаг 162 — глубина запроса числом: сначала вся схема, потом обогащение по разрешению

Заведён 2026-09-08. Репозиторий кода и учёта: `fractera-telegrambot-starter`, ветка `main`.

## 1. Пересказ и решения владельца

**Слова владельца 2026-09-08, дословно:**

> «Пришёл какой-то запрос — ты первым делом извлекаешь в себя схему всех существующих таблиц базы
> данных, чтобы сопоставить, с какими таблицами теоретически может быть связан этот запрос, и делаешь
> извлечение данных из соответствующих таблиц… проанализировал: достаточно этого для ответа или нет,
> отсеял то, что не соответствует сути запроса… либо выполнил действие, либо принял решение повторить
> запрос со вторым уровнем глубины… В случае, если недостаточно данных, спросил уточнение у
> архитектора: разрешает ли он углубиться в поиске данных, это может занять больше времени?»

> «если параметры первого уровня возвращаются почти мгновенно, то в инструкции по работе с памятью
> имел бы смысл требовать в любом случае сначала в обработку любого запроса с первым параметром,
> только последующие углубления».

> «хочу быть уверен в том, что не только вопросы чтения, но и вопросы мутации и извлечения данных
> покрывает наша сегодняшняя разработка».

**Ответ владельца на прямой вопрос об «извлечении»:** *глубина у всех четырёх глаголов.*

**И его же вопрос, которым назван мой промах:** «Разве мне об этом говорили?» — **нет**. Шаг 161
построил двузначный бюджет `fast`/`deep`, и я назвал это «сделанным наполовину». Совпадает только
самая узкая часть.

## 2. Разведка: что есть и чего нет — измерено 2026-09-08

| Что описал владелец | Что построено |
|---|---|
| уровень 1 — карта ВСЕХ таблиц, сопоставление, извлечение из подходящих | `memory_read` читает только личные признаки: **14 из 49** записей реестра, **9 таблиц из 40** |
| ответ уровня даёт данные, агент отсеивает лишнее и решает | «хватает ли» не оценивается ничем |
| не хватило — спросить разрешение, назвав время | цена называется, разрешение не требуется |
| уровни нарастают и обогащают друг друга | `deep` включается, только если на первом пусто |
| глубина у всех четырёх глаголов | глубина только у чтения |

**Где живут значения 49 признаков:** `tgdesk_messages` 17 · `tgdesk_entries` 6 · `tgdesk_artifacts` 3 ·
не хранится (ветвь разбора) 8 · личные таблицы 14 · конверт графа 1.

**Что берётся готовым:** `allFacts()` (`lib/facts/registry.ts`) · `factTableName()`
(`lib/facts/table.ts`) · `existingFactTables()` (`lib/facts/ensure.ts`) · `find()`
(`lib/registry/access.ts`) · `recall()` там же · `ask`/`learn` (`lib/fractera/knowledge.ts`) ·
`findSimilar()` (`lib/automations/similar.ts`, порог 0.33, построен и **никем не зовётся**) ·
`dataFetch` (`lib/fractera/data-service.ts`).

**Измерено о движке связей:** `DELETE /documents/delete_document`, `delete_entity`,
`delete_relation`, `POST /graph/entity/edit`, `entities/merge` — 39 путей; слой данных проксирует
`/service/rag/*` любым методом и подпутём.

## 3. Известные ограничения

| Инвариант | Что будет при нарушении |
|---|---|
| имя таблицы и колонки — только белым списком | имя из реестра станет SQL |
| `SELECT *` и `INSERT` без списка колонок запрещены | ломается там, где лестница уже дописала колонки |
| ответ чужой службы читается целиком, а не по коду HTTP | отказ засчитывается успехом |
| дверь агента называется в `proxy.ts` поимённо | `200` со страницей входа вместо ответа |
| прибор убирает за собой по своей метке | стирается живая память владельца |
| текст с обратными кавычками пишется редактором | символы теряются молча |
| число-порог без измерения — число, похожее на знание | цена уровня становится выдумкой |

## 4. Наблюдаемые результаты

1. Вопрос словами даёт **список таблиц-кандидатов** с причиной совпадения, без вызова модели.
2. Значение, лежащее в `tgdesk_entries`, **находится вопросом человека** — сегодня не находится.
3. Уровень 2 содержит всё, что дал уровень 1, плюс своё; время растёт по уровням.
4. Уровень 3 без разрешения человека отвергается с названной ценой.
5. История о постороннем **забывается**: тот же вопрос по имени её больше не находит.
6. В инструкции агента нет правила «сначала уровень 1» — оно стало конструкцией.

## 5. Порядок подшагов

162-1 карта схемы и кандидаты → 162-2 уровень 1 по всем таблицам → 162-3 число вместо выключателя,
кумулятивность → 162-4 разрешение как условие → 162-5 глубина у записи, правки, забывания →
162-6 инструкция, стандарт, доставка, приборы.

**Условие закрытия:** 162-6 последний; шаг закрывается итогом и обновлением обеих инструкций.

## 6. Решения, принятые агентом

1. Уровни 1…3, умолчание 1, **кумулятивность по устройству** — требование «сначала первый уровень»
   исполняется конструкцией, а не инструкцией.
2. **Порядок уровней по измеренной цене:** вектор (мс) ДО связей (0,9–5,0 с). Владелец в разговоре
   ставил вектор последним; расхождение названо вслух и переворачивается одной строкой в `LEVELS`.
3. **Дорогой уровень требует `approved` в самом запросе.** Запрет, который можно обойти, — не запрет.
4. Глубина у всех четырёх глаголов — прямой ответ владельца.
5. Разбор сообщений в признаки в шаг не входит.

## 7. Чего в шаг НЕ входит

наполнение второго слоя реестра.
