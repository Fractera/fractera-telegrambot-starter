# Шаг 150 — Workflow: конструктор конвейера из существующих автоматизаций

**Репозиторий:** `fractera-telegrambot-starter`. **Ветка:** `new-step-150`. **Заведён:** 2026-09-07.
**Замысел:** `PASSPORT.md` §3л. 🛑 **Кода нет: режим накопления задела.**

## Этап 1. Пересказ и решения владельца

**Просьба своими словами.** Раздел «Workflow»: поиском находим переиспользуемые автоматизации,
складываем в лист ожидания, ставим триггеры свободной фразой — получается конвейер, который живёт в
календаре и по очереди запускает свои шаги.

**Слова владельца дословно (2026-09-07):** «конвейерная автоматизация которая будет внутри одной
автоматизации последовательно по триггеру запускать другие автоматизации, так называемый Workflow…
вот кстати запомни то чего у нас нету на фундаментальном уровне, одно из свойств автоматизации: эта
автоматизация может переиспользоваться в Workflow. Это признак самой автоматизации, её базовой
таблицы автоматизаций» · «добавить в лист ожидания… набрасываем различные автоматизации в копилку…
устанавливаем триггер, например: автоматизация номер четыре доступна после автоматизации номер три
через один день. В свободной форме пишем… который как одна последовательная автоматизация живёт свою
жизнь в календаре».

**Мои решения самостоятельно.**
1. **Второго движка нет:** конвейер собирается из закрытия шага (§3е) и календаря (§3и); новое —
   только определение и конструктор.
2. **Переиспользуемость выводится из ДОГОВОРА вход-выход**, а не объявляется галочкой: иначе
   появятся отмеченные автоматизации, которые нельзя вставить.
3. **Триггер хранится типизированным**, свободная фраза — только вход. Исполняемое правило из текста
   зависело бы от прочтения модели каждый раз.
4. **Определение, прогон и шаг прогона — три разные вещи**; прогон помнит версию шага.
5. **Лист ожидания — черновик конвейера**, а не новая сущность.

## Этап 3. Известные ограничения

🛑 Календарь пуст: конвейер поверх мёртвого календаря не запустится вовсе.
🛑 Квота одна на всех: конвейер без потолка способен съесть её целиком.
Всё, по чему отбирают, обязано быть колонкой · модель на входе, типизированное на выходе ·
цикл проверяется при сохранении, а не при запуске.

## Этап 4. Наблюдаемые результаты

1. У автоматизации есть договор входа-выхода, и из него выводится переиспользуемость.
2. Поиск «покажи автоматизации, связанные с YouTube» возвращает только переиспользуемые.
3. Автоматизация добавляется в лист ожидания и переживает уход со страницы.
4. Фраза «№4 после №3 через день» превращается в **видимое правило**, которое правится руками.
5. Попытка замкнуть цикл отвергается при сохранении с названными участниками.
6. Запуск конвейера порождает прогон со своим номером; правка определения не меняет прошлые прогоны.
7. Прогон движется через календарь: закрытие шага ставит следующую ступень.
